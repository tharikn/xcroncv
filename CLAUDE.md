# XCron CV - working conventions
- Independent platform (own repo, DB, API). Never import X Cron internals or read its DB.
- Local source folder reference: `D:\Projects\x-cron` (host app). Resume docs live in `D:\Projects\x-cron\docs\resume-builder`.
- Every route needs auth (deny-by-default AuthGuard). `@Public()` is for /health, `POST /auth/exchange` (host handoff, throttled, see docs/INTEGRATION.md), plus the single token-addressed, read-only anonymous portfolio view `GET /public/portfolios/:token` (doc 41, `PublicPortfolioController`). Do not add other public routes.
- userId/tenantId come from the verified token, never from request bodies. Every resume query filters by tenant AND owner.
- No generated PDF/HTML/DOCX/XLSX bytes or uploaded source files are ever persisted server-side. Stream and discard.
- Preview and export share one render model (`src/render-model`). No separate layout logic.
- Templates are declarative, immutable, versioned (`src/templates/template.catalog.ts`). Ship a new `version`, never edit one.
- AI is optional, never decides numeric scores, never persists unconfirmed facts.
- Scores (ATS, match, quality, parsing) stay separate and versioned.
- Change log: every change must add a row (date, change, files, tests) to the **Change log** of the owning `docs/modules/*.md`, and cross-module changes to `docs/CHANGELOG.md`. Update HLD/LLD/TESTING when architecture or test commands change. See `docs/CHANGELOG.md`.
- i18n: no hardcoded UI strings in templates or toasts. Use `| t` keys in `core/i18n/en.ts` and add the same keys to `ta.ts` and `hi.ts` (a Jest test enforces parity). Theme via tokens in `styles.scss`, never hard-coded colors.
- Env files: `apps/api/.env` (local), `apps/api/env-dev` (**live production only**: Render hosts, prod DB, prod CORS/JWKS/handoff; no localhost; gitignored) and `.env.example` (committed, no secrets). Any env key change must update all three together. DB is shared with X Cron: set `DATABASE_URL` without `?schema=` and `DB_SCHEMA=xcroncv`; never use `public` or the `xcron` schema.
