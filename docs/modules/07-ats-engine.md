# Module 07 - ATS Compatibility Engine (doc 07)

A standalone, deterministic ATS compatibility estimate for **one resume and one job posting**. It has its own route (`/ats`, card on the Career tools hub), service, report history, score and version. It reuses shared matching primitives (taxonomy, job-description requirements, evidence matcher from module 23/29) but is **never added to, blended with, or presented as** the Resume Match score (doc 23), the Quality score (doc 20) or the Parsing Test score (doc 21).

## API
| Route | Purpose |
|---|---|
| `GET /ats/model` | Versioned dimensions, weights and disclaimer (no user data; still behind the auth guard) |
| `POST /resumes/:resumeId/ats-reports` `{ jobDescriptionId, resumeVersionId? }` | Score the working draft or an immutable saved version against a stored job description |
| `GET /resumes/:resumeId/ats-reports` | History (50 newest) |
| `GET /ats-reports/:id`, `DELETE /ats-reports/:id` | Read / delete one report |

Every query filters by tenant AND owner (resume via `ResumesService.get`, job description and report directly). Foreign ids give a non-disclosing 404. The JD must already exist (`POST /job-descriptions` in module 23/29), so the user has seen and can confirm the extracted requirements; an unconfirmed posting is scored with a visible limitation and lower confidence.

## Score model - `ats-1.0.0` (`ats-engine.ts`)
| Dimension | Weight | Source |
|---|---:|---|
| Required skills match | 20 | matcher items: demonstrated in work = 1, listed only = 0.5, related = 0.4, missing = 0 |
| Preferred skills match | 10 | same |
| Relevant experience evidence | 20 | years, responsibilities, demonstration ratio (skills shown in work, not only listed) |
| Role/title relevance | 10 | JD title and seniority vs resume |
| Keyword coverage | 10 | every distinct posting keyword counted **once** (no keyword stuffing credit) |
| Semantic relevance | 10 | lexical cosine only, no AI model |
| Structure/parseability | 10 | own rules: contact, recognisable headings, core sections, readable consistent dates, order, table-like text |
| Content clarity/completeness | 10 | own rules: summary, role detail, bullet length, action verbs, figures, overall length |

- Dimension score = mean item points x 100. A dimension with nothing to evaluate is **not applicable**; its weight is redistributed over the applicable ones (`effectiveWeight`), never scored as zero. Total = weighted mean over applicable dimensions.
- Structure and clarity need no job, so a score exists even for a posting with no usable requirements (confidence then `low`).
- Each dimension returns score, max (100), weight, effective weight, matched / weak / missing labels, and explanation. Each item has status, method, explanation, located resume evidence excerpts (<= 160 chars) and an honest action ("Add X only if it reflects work you have actually done").
- Wording: "not found in this resume", never "you lack the skill". Education-first order is not penalised. Gaps and unusual layouts are explained, not punished silently.
- Confidence (`high|medium|low`) and limitations are reported (unconfirmed requirements, redistributed weight, few requirements, structure checks use the render model not an exported file).
- No LLM decides or adjusts any number. `ATS_VERSION` must be bumped whenever weights, thresholds or rules change; the taxonomy version is stored too. Old reports keep their version and meaning.

## What is stored (`AtsReport`)
Tenant/owner ids, resume id + version id/number + content hash, job description id + revision + title/company (plain references, no FK, so history survives deletes), versions, score, dimensions, items (short located excerpts) and coverage. **Not stored**: resume text beyond excerpts, contact details, JD text, any document bytes. No file is read or generated by this module.

## Web (`apps/web/src/app/features/ats-engine`)
Resume + version + job pickers, guidance when there is no resume or posting (links to Job match), big score with confidence and disclaimer, eight dimension cards with a bar **and** a text band (Strong / Partly supported / Needs attention, never colour only), N/A explanation, expandable checks sorted weakest first with evidence and suggestion, strong matches, weak/not found, improvements, history with confirm-before-delete, and an "About this score" panel with the weights. Responsive, no horizontal overflow, axe clean (checked in e2e).

## Tests
- `apps/api/test/ats-engine.spec.ts` (21): weights/total, determinism and immutability, evidence and honest wording, listed-vs-demonstrated, keyword-once, N/A redistribution, unconfirmed limitation, excluded requirements, structure/clarity rules, education-first order, score separation (no match fields), service tenant+owner scoping, no contact data stored, feature flag.
- `apps/web/e2e/ats-engine.spec.ts` (8 x 4 device profiles): auth, hub, empty states, scored report with dimensions/evidence/N/A, confirmed vs unconfirmed confidence, history + delete confirm, error state, overflow + axe. Fake API: `e2e/support/mock-ats.ts` (postings come from the insights mock).

## Known gaps
- Weights are initial values; calibration against anonymised postings/resumes and human reviewer judgments is not done (doc 07 s7). Do not treat thresholds as validated.
- No semantic/embedding adapter (lexical overlap only) and no per-employer ATS emulation (by design).
- Structure checks run on the render model; exported-file parsing diagnostics stay in the Parsing Test (module 07 parsing doc).
- Prisma: new table `AtsReport`; run `npm run db:migrate`. Feature flag: `FEATURES_DISABLED=ats-engine`.
